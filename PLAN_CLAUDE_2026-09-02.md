## 0. Диагноз: почему Codex не доходил до финиша

1. **Самоблокирующийся процесс.** Codex ввёл 8 «gate» (NE-01…NE-08) + 6 «packaging gates» (P0…P5), «sole editor» + 4 агента-аудитора, sealed-evidence пакеты с SHA всего. Каждая правка продукта требовала цепочку правок хешей в тестах (`tools/thermogar_vlb_*_static_test.py` пинят SHA других тестов, те — SHA файлов приложения), затем «независимого аудита», затем ещё раунда (R1…R14). Один рабочий день уходил на 3–6 раундов аудита без продвижения функциональности.
2. **Продукт заморожен политикой.** `app/thermogar_release_policy.py`: `CALCULATIONS_ENABLED = EXPORTS_ENABLED = IMPORTS_ENABLED = False`. Из-за этого в приложении **отключены** кнопки: 4 диаграммы, затвердевание, 3 энергии, диффузия, KWN-выделения, и **все 27+ кнопок скачивания** (Excel/CSV/PNG). Codex решил «не переключать флаг», а переписывать каждый маршрут через «verified loaders» (волны B1…B7) — дошёл до B4B2 из семи, потом переключился на установщик для урезанной программы.
3. **Последний блокер (02.09)** — не продукт, а собственный тестовый harness: синтетический PowerShell-тест жизненного цикла лаунчера (100 кейсов, 78 КБ) падает с exit 6 из-за коллизии фейковых HANDLE в самом тесте.
4. Нет git. История — сотни md-отчётов и ручных SHA.

## 1. Реальное состояние (проверено по коду)

**Работает** (через verified-маршрут): выбор базы Ni/Al/Сталь; равновесие — одна точка, скан по T, скан по составу (для Стали — только 3 точки); batch CSV/XLSX; плотность; упругие модули (VRH); вклады упрочнения; паспорт базы; проекты/библиотека сплавов/история (частично).

**Заблокировано политикой** (код есть, кнопка `disabled`): бинарная диаграмма, изоплета, тройная диаграмма, карта доли фазы, затвердевание (равновесное/Scheil), энергии фаз, движущая сила, T₀, диффузия/гомогенизация, KWN-выделения, все скачивания, импорт файлов.

**Сталь**: hard-reject `fe` в `thermogar_diffusion.py:167`, `thermogar_precipitation.py:514`, batch в `thermogar_workspace.py`; C15_LAVES фильтруется только в 3 Core1-маршрутах, в остальных (диаграммы, затвердевание, энергии) — нет; спец-ветка «2000 K» в затвердевании считает C15 — удалить.

**Установщик**: `packaging/` содержит рабочие заготовки — `launcher.pyw` (stdlib, LocalAppData, loopback health), `stop.pyw`, `healthcheck.py`, `ThermoGar.nsi`, `build_installer.ps1`, `stage_payload.ps1`, иконка `assets/ThermoGar.ico`. Бандл-рантайм CPython 3.11.9 — `ThermoGar-Installer-Assets/runtime-clean-3119`. NSIS ожидается в `C:\Program Files (x86)\NSIS`. Существующий `dist/ThermoGar-0.2.0-ne02-win64.exe` (119 МБ) — сборка урезанной версии, финалом не является.

**Окружение**: `.venv-windows` (Python 3.11.9; pycalphad 0.11.2, kawin 0.5.0, scheil 0.3.0, streamlit 1.62, numpy 2.4, scipy 1.17, symengine 0.13). Запуск: `RUN_THERMOGAR_WINDOWS.cmd`. Тесты: 47 файлов в `tools/`, из них функциональные ~15, остальные — sentinel/аудит Codex.

## 4. Риски

- Размер `ThermoGar_app.py` (430 КБ, ~11 000 строк) — правки точечные, без рефакторинга «ради чистоты».
- Verified-маршрут (B2–B4B) остаётся для равновесий/свойств; остальные разделы работают старым прямым путём. Смешение допустимо; унификацию не делаем.
- Время расчётов на Fe-базе (2.062, ~сотни фаз) — возможны минуты на диаграммах; ограничить сетку по умолчанию, показывать прогресс.
- NSIS должен быть установлен; проверить в Э5 первым шагом.
- Отсутствует второй чистый ПК для проверки установщика — использовать VM (Hyper-V/VirtualBox) или Windows Sandbox.
