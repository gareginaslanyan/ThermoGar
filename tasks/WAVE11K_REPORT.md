указывает SHA-256 базы, к которой применим, и загрузчик отказывается накладывать

В поставку файл попадает сам: `packaging/stage_payload.ps1` копирует

### Почему число не подставлено

Ни один первоисточник по тепловому расширению хрома сессии не открылся:

* ScienceDirect и APS отдают `HTTP 403 Forbidden`;
* свободный скан NBS 1941 года доступен, но читается только через OCR-слой, а он
  в той же таблице врёт: соседняя колонка выходит как «0.7to 8.3». Числа из
  такого слоя — не прослеживаемый источник;
* справочные однозначные величины расходятся между собой (CRC, Lange и
  Touloukian дают 4,9·10⁻⁶/K при 25 °C, инженерные таблицы — 6,2·10⁻⁶/K, и
  задание называет 6,2), и любая из них — одна точка при комнатной температуре,
  тогда как перекрывать нужно весь наклон ρ(T) до 1100 °C.

Список с DOI подан отдельным файлом `tasks/SOURCES_WANTED.md`, позиция `S-1`,
шесть позиций по убыванию полезности. Отдельно выделена позиция 5 — сама REF 14
базы (Lu, Selleby, Sundman, Calphad 29 (2005) 68–89): если в статье стоит
нормальное число, дефект окажется опечаткой при переносе в базу, и правка будет
не нашей оценкой, а восстановлением источника. Это меняет формулировку
перекрытия, поэтому проверять её стоит первой наравне с прямыми измерениями.

Чтобы поправка заработала, нужно заполнить `expression` и `source` и поставить
`enabled: true`. Кода и тестов трогать не придётся.

## 11K-4. Регрессия

### Чего не вышло: одной строки на весь `tools/` нет

Прогон всего каталога одной командой не доходит до конца **ни разу**. Две
независимые причины, обе найдены этой волной:

1. **kwn-тесты выбирают собственный `@pytest.mark.timeout`**, а метод `thread`
   на Windows убивает весь процесс pytest, а не только тест. Прогон обрывается
   дампом стека без итоговой строки:

   ```
   +++++++++++++++++++++++++++++++++++ Timeout +++++++++++++++++++++++++++++++++++
   ~~~~~~~~~~~~~~~~~~~~~~~~~ Stack of MainThread (11884) ~~~~~~~~~~~~~~~~~~~~~~~~~
   ...
   File "...\kawin\thermo\MultiTherm.py", line 419, in getGrowthAndInterfacialComposition
   ```

2. **`test_parallel_engine.py::test_sequential_and_parallel_agree_bytewise`
   зависает** на вложенном пуле воркеров. Дочерний процесс
   `test_parallel_engine.py --identity` живёт, но 0 с процессорного времени и
   2 МБ рабочего набора — полчаса без движения. Снятие воркера прогон не
   оживило.
