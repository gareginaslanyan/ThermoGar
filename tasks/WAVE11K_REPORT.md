## 11K-2. Плотность хрома: перекрывающий слой

выключено.** Причина — указание мастера, пришедшее во время работы над пунктом:
источники обходными путями не добывать, а при недоступности первоисточника
механизм построить полностью, поле величины и поле источника оставить пустыми,
перекрытие выключить и подать список с DOI.

### Что сделано

**1. Байты `physical_data_v103.pdb` не тронуты.** Заведён отдельный файл
`databases/physical/overrides/physical_data_v103.overrides.json` — собственный
формат `thermogar-physical-override` версии 1, рядом с базой. Первым же полем
идёт `notice`: «ЭТО ПРАВКА ПРОЕКТА ThermoGar, А НЕ ДАННЫЕ ИСТОЧНИКА». Файл
указывает SHA-256 базы, к которой применим, и загрузчик отказывается накладывать
его на другую базу.

В поставку файл попадает сам: `packaging/stage_payload.ps1` копирует
`databases\physical` рекурсивно.

**2. Содержимое записи.** Заполнены: перекрываемая величина (`FUNCTION DTCRBCC`,
строка 137 базы, с перечислением того, на какие `PARAMETER DP` она влияет и на
какие нет), исходное выражение базы, причина правки, дата, волна, грамматика
будущего выражения и ограничения на него, доказательства дефекта, текст для
пользователя. Пустыми оставлены ровно два поля: `expression` и `source`, статус
записи — `pending_source`.

**3. Перекрытие видно пользователю.** Применённая правка кладёт свой текст
**первым** в `warnings` результата расчёта плотности. Интерфейс рисует эти тексты
через `st.warning` в обеих панелях плотности — при одной температуре это было
уже так, для расчёта по температуре вывод предупреждений добавлен этой волной.
Проверяется тестом `test_override_is_announced_in_the_result`.

**4. Перекрытие отключается тремя независимыми способами:**

* переменная окружения `THERMOGAR_PHYSICAL_OVERRIDES=off` (а также `0`, `no`,
  `false`, `нет`, `выкл`) — файл при этом даже не читается. Способ назван прямо
  в тексте самой поправки, которую видит пользователь;
* `"enabled": false` в файле-дополнении;
* `PhysicalDensityDatabase(path, overrides=None)` в коде и тестах.

Задокументировано в `docs/DATABASES.md`, новый раздел 8 «Поправки проекта к
физической базе».

### Проверка механизма без подстановки литературного числа

Чтобы механизм не остался непроверенным, он прогнан на подмене, взятой не из
литературы, а **из самой базы**: в `physical_data_v103.pdb` закомментирована
строка 136 — более ранний вариант той же функции `DTCRBCC` по REF 10 (Smithells
7-е изд.). Временный файл лежал в каталоге сессии, в репозиторий не попал.

```
applied: ['cr-thermal-expansion']
DTCRBCC plain : +73.9748-0.263244367*T-0.00013071*T**(+2)-0.000000073784*T**(+3)
DTCRBCC mech  : +32.5-0.082*T-9.5E-05*T**(+2)
plain  Cr rho(25)=7181.9 rho(1100)=6475.0  alpha_mean=32.69e-6/K
mech   Cr rho(25)=7199.6 rho(1100)=6940.8  alpha_mean=11.42e-6/K
plain  matrix alpha_mean(25..1100) = 20.77e-6/K  in window False
mech   matrix alpha_mean(25..1100) = 14.82e-6/K  in window True
```

Вывод: механизм работает от файла до результата, и подмена одной функции
действительно переводит коэффициент расширения матрицы из 20,8·10⁻⁶/K в
14,8·10⁻⁶/K, то есть внутрь окна 12…20. Ожидание задания подтверждено.

Разница с числом задания: задание называет нынешние 21,2·10⁻⁶/K, измерено
20,77·10⁻⁶/K. Расхождение 2 % и, скорее всего, от способа усреднения; на вывод
не влияет — окно всё равно не выполняется.

### Почему число не подставлено

Ни один первоисточник по тепловому расширению хрома сессии не открылся:

* ScienceDirect и APS отдают `HTTP 403 Forbidden`;
* свободный скан NBS 1941 года доступен, но читается только через OCR-слой, а он
  в той же таблице врёт: соседняя колонка выходит как «0.7to 8.3». Числа из
  такого слоя — не прослеживаемый источник;
* справочные однозначные величины расходятся между собой (CRC, Lange и
  Touloukian дают 4,9·10⁻⁶/K при 25 °C, инженерные таблицы — 6,2·10⁻⁶/K, и
  задание называет 6,2), и любая из них — одна точка при комнатной температуре,
  тогда как перекрывать нужно весь наклон ρ(T) до 1100 °C.

Список с DOI подан отдельным файлом `tasks/SOURCES_WANTED.md`, позиция `S-1`,
шесть позиций по убыванию полезности. Отдельно выделена позиция 5 — сама REF 14
базы (Lu, Selleby, Sundman, Calphad 29 (2005) 68–89): если в статье стоит
нормальное число, дефект окажется опечаткой при переносе в базу, и правка будет
не нашей оценкой, а восстановлением источника. Это меняет формулировку
перекрытия, поэтому проверять её стоит первой наравне с прямыми измерениями.

Чтобы поправка заработала, нужно заполнить `expression` и `source` и поставить
`enabled: true`. Кода и тестов трогать не придётся.
