
Прогон шёл с `THERMOGAR_STATE_ROOT=~/ThermoGar/results/validation/wave16_a_state`, как
сказано в задании. Причина одна на всех трёх базах (ni, al, fe). Приложение
показывает на экране:

```
Проверенная привязка базы отклонена: ARTIFACT_IO_FAILED: Pinned artifact read failed:
Secure ancestor-pinned file operations require Windows.
```

Источник — `app/thermogar_secure_io.py:150`, `_require_windows_pinning()`: при
`os.name != "nt"` чтение привязанного файла запрещено всегда. От `THERMOGAR_STATE_ROOT`
это не зависит: обход из задания («если secure_io отказывает — STATE_ROOT») здесь не
помогает. Отказ идёт до экрана базы, поэтому краснеют все тесты, которым нужна база:
например, `test_kinetics_section_renders[ni]` не находит кнопку `kin_single_run_ni`.
Код `app/` менять нельзя, поэтому на этой машине тест зелёным не станет.

Для решения мастера: сам расчёт 16-А от этого запрета, по чтению кода, не зависит.
`tools/study_wave16_a_lilith.py` читает файл базы через `read_bytes()` и сверку sha
(`load_db`), а не через `thermogar_secure_io`. Скрипт «Лилит» тоже читает файл сам. Это
не проверено запуском: по условию задания после красных тестов я ничего не запускал.

Варианты:
1. Снять условие «0 красных» для мака. Проверка тогда такая: 25 красных, причина одна —
   запрет не-Windows в `_require_windows_pinning`. Шаги 1–5 идти как в задании.
2. Считать шаг 0 невыполнимым на маке без правки `app/` и перенести 16-А3 на другую
   машину с Windows.
