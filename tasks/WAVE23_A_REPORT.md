## Что сделано

1. **Оболочка `desktop/src-tauri`** (Rust, ~200 строк). Запускает прежний `launcher.pyw`,
   читает `ui_port` из `%LOCALAPPDATA%\ThermoGar\runtime\run.json`, проверяет `/_stcore/health`
   и открывает окно 1440×900 с заголовком ThermoGar. К уже работающему экземпляру подключается,
   второй не поднимает.
2. **Заставка и страница ошибки** (`desktop/src/index.html`, `error.html`). Разбор базы занимает
   20–60 с; пустое окно читалось бы как зависание. Если порт не появился за 260 с, окно
   показывает причину и что проверить.
3. **`launcher.pyw`** получил одну проверку: при `THERMOGAR_NO_BROWSER=1` не зовёт
   `os.startfile`. Замок запуска, запись `run.json`, job-объект, проверки целостности установки
   и здоровья не тронуты и остаются единственным источником правды о том, запущена ли программа.
4. **NSIS** (`packaging/ThermoGar.nsi`): ярлыки ведут на `ThermoGar.exe`, добавлена проверка его
   наличия наравне с рантаймом, деинсталлятор его удаляет.
5. **Поставка** (`packaging/stage_payload.ps1`): exe добавлен в `$SingleFiles` и в
   `$RequiredInStage`; без него стейджинг падает с `PAYLOAD_SOURCE_MISSING` — намеренно.
6. **Приёмка** (`packaging/smoke_installed.ps1`): шаг 3 и `Start-InstalledApp` запускают
   `ThermoGar.exe`, а не `pythonw launcher.pyw` — проверяется тот путь, которым идёт пользователь
   по ярлыку. `ThermoGar.exe` добавлен в список обязательных файлов.
7. **Версия 0.6.0**, `CHANGELOG.md`, `HANDOFF.md`, `THIRD_PARTY_NOTICES.txt` (перегенерация
   сборкой), `.gitignore` (`desktop/src-tauri/target/`).

## Дефекты, найденные приёмкой и владельцем, закрытые в этой же волне

### 1. Оболочка жила после остановки лаунчера (`b6a70c8`)

Первый прогон приёмки: **7 из 8 PASS, шаг 7 FAIL** — после удаления оставался `ThermoGar.exe`.

Причина не в деинсталляторе. Оболочка ждала только `RunEvent::ExitRequested`, поэтому после
`stop.pyw` (и после удаления, которое останавливает приложение) окно продолжало жить, показывая
страницу от мёртвого процесса, и держало exe открытым. Три процесса `ThermoGar.exe` висели
4 минуты; файл был залочен, `Delete` в деинсталляторе не срабатывал.

Исправлено слежением за дочерним процессом раз в секунду: умер лаунчер — оболочка выходит.
Повторный прогон — шаг 7 `leftover files 0`, на диске после прогона чисто.

### 2. Второе окно — вкладка браузера (`eca749f`), найдено владельцем

Владелец запустил 0.6.0 по ярлыку и увидел два окна: окно оболочки и вкладку браузера на
`127.0.0.1:<порт>`.

Причина: `launcher.pyw`, `_open_ui` зовёт `os.startfile(f"http://127.0.0.1:{port}/")`. Это было
правильно, пока ярлык запускал сам лаунчер — иначе пользователь не видел вообще ничего. С
оболочкой вкладка стала вторым окном на один запуск.

Исправлено: оболочка запускает лаунчер с `THERMOGAR_NO_BROWSER=1`, тот флаг уважает. Прямой
запуск `launcher.pyw` без оболочки открывает браузер как раньше — старый сценарий не сломан.

Проверено фактом: процессов Edge с `127.0.0.1` в командной строке до запуска 1 и после 1 (та же
старая вкладка на порту 50031); для нового `ui_port` 49219 вкладки не появилось.

### 3. Окно ждало не того ответа (`cf1c412`), найдено по жалобе «медленно, не сразу»

| Событие | Время |
|---|---|
| `/_stcore/health` отвечает 200 | **2,6 с** |
| `/_stcore/script-health-check` отвечает 200 | **21,9 с** |

Второй ждёт завершения первого прогона `ThermoGar_app.py`. Оболочка ждала именно его — все
девятнадцать секунд между ними пользователь видел пустой рабочий стол.

Исправлено: окно открывается по `/_stcore/health`; остаток загрузки прикрывает индикатор
Streamlit внутри окна. Замер после правки: **окно видно на 0,3 с**, приложение готово на 21,5 с.

**Кэш разобранной базы проверен отдельно — он уже работает, отдельной работы не требует.**
`thermogar_db_cache.load_or_parse`: 0,4 с против 16,4 с холодного `Database.from_file`. Все три
базы из кэша за 0,3–0,4 с. Импорты дают около 5 с, из них pycalphad 4,3 с.

**Что осталось:** около 16 с первого прогона — сам скрипт приложения под Streamlit, не базы и не
импорты. Профилировать `ThermoGar_app.py` изнутри Streamlit — отдельная задача.

## Отступления и замечания

1. **Тулчейн ставился с нуля.** На машине не было ни Rust, ни Node, ни MSVC. Поставлены:
   Rust 1.99.1 (rustup, профиль minimal), Node v24.19.0, MSVC BuildTools 17.14.44 с Windows SDK
   10.0.22621.0. Установщик MSVC попросил перезагрузку — для линковки она не понадобилась.
2. **`Set-Content -Encoding UTF8` в PowerShell 5.1 пишет BOM**, и парсер Tauri его не принимает
   (`unable to parse JSON ... expected value at line 1 column 1`). Все файлы оболочки
   перезаписаны через `[IO.File]::WriteAllText` с `UTF8Encoding($false)`.
3. **`tauri::State` не подошёл**: guard заимствует app handle и переживает его в потоке и в
   колбэке события (`E0597`). Состояние держится в `Arc<Mutex<Option<Child>>>`.
4. **`tauri.conf.json`: `bundle.active = false`.** Установщик собирает NSIS, а не Tauri.
5. **Подпись кода отсутствует** — решение владельца: «нет сертификата, пускай ругается».
