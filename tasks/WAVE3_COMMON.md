## Что значит «раздел работает»
Для каждой ячейки матрицы (действие × база Ni/Al/Fe): через `streamlit.testing.v1.AppTest` выбрать базу, задать состав и
параметры, нажать кнопку расчёта, дождаться результата — без `at.exception`, без `st.error` (кроме ожидаемых валидационных),
результат содержит осмысленные данные (таблица непустая, доли фаз в сумме 1, график создан); затем **экспорт**: вызвать те же
функции, что стоят за кнопками скачивания (`dataframe_to_excel`, `figure_to_png`, CSV), и проверить байты — Excel открывается
`openpyxl`, PNG начинается с `\x89PNG`, CSV парсится `pandas`. Если `AppTest` не даёт добраться до кнопки скачивания —
допустимо проверить экспорт на уровне функций с результатом из session_state.

Составы (как в 1C): Ni–15Al ат.%; Al–4Cu–1Mg масс.%; Fe–0.2C–11.5Cr–0.7Ni масс.%. Температуры: Ni 700 °C, Al 500 °C, Fe 700 °C.
Сетки — минимальные разумные (диаграммы на грубой сетке; Al дорогая: тройное 282 с, карта 222 с — брать ещё грубее).
`AppTest(..., default_timeout=900)`. Тесты, где расчёт > 60 с, — под маркером `slow`.

## Что чинить, а что нет
- Чинить: падения, `NameError`, пустые результаты, неработающий экспорт, неверные единицы/подписи, кнопки, которые ничего не делают,
  расхождение UI и бэкенда (бэкенд считает — UI нет), стейл-результаты после смены базы. Ошибки валидации, которые
  срабатывают неправильно.
- Не чинить, а записать: научные вопросы (какая фаза должна быть матрицей), долгие расчёты сами по себе (только ограничить
  дефолтную сетку), отсутствующие данные в PDB (Al: нет THETA_AL2CU — показать честно как «покрытие 98.9 %»).
- Не менять численные алгоритмы, TDB/PDB; не вводить SHA-пины; C15 для Fe не возвращать; названия фаз бэкенда (`GP_MAT`,
  `BCC_B2`) можно **подписывать** понятно в UI (например «BCC_B2 (BCC/феррит, связанная модель)»), но не переименовывать в данных.
