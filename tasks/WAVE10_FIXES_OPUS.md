## A3. Дублирование параметров подвижности → неверный коэффициент диффузии

**Дефект.** В `databases/converted/mc_ni_v2036_with_mobility.garcalc.tdb` параметр подвижности задан дважды с одинаковым выражением:

```
PARAMETER MQ(FCC_A1&MO,*)     273.00  -267585-79.5*T; 6000.00  N
PARAMETER MQ(FCC_A1&MO,NI:*)  273.00  -267585-79.5*T; 6000.00  N
```

pycalphad их **складывает**, kawin отдаёт квадрат коэффициента диффузии (√(kawin)/база = 1,0001 — то есть ровно квадрат). Штатный `run_diffusion` не выравнивает профиль вообще.

Явление системное, не единичное. Замер по трём базам:
- `mc_ni`: **10 из 28** wildcard-параметров продублированы,
- `mc_al`: **7 из 15**,
- `mc_fe`: **7 из 79**.

**Сделать.**
- **Базу не править.** Дедупликацию делать после разбора TDB, в загрузчике: для каждой пары (фаза, диффундирующий элемент, тип параметра) если найдены параметр с полностью wildcard-констituent array и параметр с явным `NI:*`/`FE:*`/`AL:*` при **идентичном** выражении — оставлять один (явный), второй отбрасывать.
- Сравнение выражений — символьное (`sympy.simplify(a - b) == 0`), не строковое: пробелы и порядок слагаемых различаются.
- Если выражения **различаются** — это не дубль, ничего не отбрасывать, записать в лог как подозрительное место и оставить поведение pycalphad как есть.
- Логировать: `дедупликация подвижностей: mc_ni — отброшено N параметров`. Число вывести в паспорт базы, чтобы было видно в UI.
- Кэш баз (`app/thermogar_db_cache.py`) инвалидировать: ключ кэша сейчас = SHA TDB + версия pycalphad. Добавить в ключ версию логики дедупликации, иначе пользователи со старым кэшем получат старое поведение.

**Тесты** (`tests/test_mobility_dedup.py`) — проверять физику, не факт вызова:
1. `D(Mo)` в FCC-Ni при бесконечном разбавлении, 1200 °C, после дедупликации — сверить с прямым расчётом из выражения `MQ` вручную (`D = RT/… exp(MQ/RT)` по формуле базы). Совпадение до 1e-6 относительных.
2. До правки этот же расчёт даёт **квадрат** — зафиксировать это в тесте как «было» через явный расчёт с продублированным параметром, чтобы регрессия ловилась.
3. `run_diffusion`: пара полубесконечных областей с разным содержанием Mo, выдержка, при которой аналитическое решение даёт выравнивание до 50 % от начального перепада. Утверждение — **состав изменился**: перепад упал не менее чем на 40 %. Текущие тесты проверяют только баланс массы и форму профиля и потому дефект пропустили.
4. Порядок величины: `D(Mo)` в FCC-Ni при 1200 °C после исправления должен лежать в 1e-15…1e-13 м²/с. Литературный ориентир для Mo в Ni при 1200 °C — порядка 1e-14 м²/с; тест на разумность диапазона, не на точное значение.

**Отдельно к проверке.** В волне 9 `D(Mo)` при составе сплава оказался **на два порядка выше** разбавленного предела той же базы. После дедупликации пересчитать. Если разрыв сохранится — это уже не дубль, а параметры взаимодействия подвижности; тогда не чинить, а описать в отчёте с числами и оставить решение мастеру.

## A4. Плотность — самый сложный пункт

### A4.2. Молярный объём FCC_A1 завышен в 1,7–1,8 раза

Для Ni–Cr–Mo выдаётся 12,13 см³/моль атомов против ≈7,0. Плотность матрицы — 4,9 г/см³ вместо ≈8,9. Корень в волне 9 не найден.

**Важно:** данные в PDB корректны, я проверил. Файл хранит **плотность**, не молярный объём:

```
FUNCTION D0FCC_NI  ...  8914.0   (кг/м³, верно для Ni)
FUNCTION D0BCC_CR  ...  7200.0   (верно)
FUNCTION D0BCC_MO  ... 10223.8   (верно)
```

Ошибка в коде смешения `app/thermogar_physical.py`, не в данных.

**Диагностика — сделать в этом порядке, это бисекция, она экономит часы.**

Шаг 1. Чистый Ni, FCC_A1, 298,15 K. Что выдаёт код?
- Если **не** 8914 кг/м³ → ошибка в формуле объёма одной фазы. Смешение ни при чём.
- Если 8914 кг/м³ → ошибка в правиле смешения. Переходить к шагу 3.

Шаг 2 (если чистый Ni неверен). Гипотезы по убыванию вероятности:
- **H1 — считается моль формульных единиц вместо моля атомов.** `FCC_A1` в mc_ni имеет две подрешётки, вторая — межузельная `(VA)`. Если объём делится на число молей узлов, а не атомов, получается ровно ×2. Наблюдаемое 1,84 — это ×2 с поправкой на частичное заполнение межузельной подрешётки углеродом. **Это главная гипотеза, проверять первой.** Смотреть, как из `Model` берётся нормировка: `moles(атомы)` против суммы site ratios.
- **H2 — единицы.** кг/м³ против г/см³ вместе с ещё одним множителем.
- **H3 — тепловое расширение** применяется к плотности с неверным знаком или в неверной степени (ρ ∝ 1/V, а не ∝ V; и ×3 для линейного/объёмного коэффициента).

Шаг 3 (если чистый Ni верен, а сплав нет). Правило смешения. Плотности смешиваются **по массе**, а не по мольной доле:

```
верно:   1/ρ = Σ wᵢ/ρᵢ,  где wᵢ — массовые доли
неверно: ρ   = Σ xᵢ·ρᵢ,  где xᵢ — мольные доли
```

Проверить, какая формула в коде. Для контрольного состава разница между ними невелика, поэтому если расхождение 1,8× — дело скорее в шаге 2, но проверить всё равно.

**Приёмочные тесты** (`tests/test_density.py`):
1. Чистые элементы при 298,15 K: Ni 8914, Cr 7200, Mo 10223,8 кг/м³ — совпадение с PDB до 0,1 %.
2. Матрица контрольного состава (только FCC_A1) при 25 °C: **8,5–8,7 г/см³**. Это опорное значение: сплавы Ni–Cr–Mo типа C-4/C-276 имеют 8,6–8,9 г/см³, обеднение хромом даёт нижнюю границу.
3. Сплав целиком при 1100 °C (γ + следы MnS): плотность в пределах 8,2–8,6 г/см³ (тепловое расширение).
4. Монотонность: ρ(T) убывает на всём интервале 25…1300 °C. Ловит перевёрнутый знак расширения.
5. Проверить те же три элемента по алюминиевой и стальной базам: Al ≈ 2700, Fe ≈ 7874 кг/м³.

**Если после шагов 1–3 корень не найден** — не гадать дальше. Зафиксировать в отчёте: что проверено, какие числа получены на каждом шаге, какая гипотеза отпала и почему. Плотность временно скрыть в UI с пометкой «в разработке», чем показывать заведомо неверное число.
