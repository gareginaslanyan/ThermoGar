## Цель
Сканы по T и по составу, карта доли фазы, плотность по T и пакетный расчёт считают точки через
`ParallelEquilibrium` для всех трёх баз; одиночное равновесие, диаграммы (mapping) и Scheil — как были.
Числа побайтово совпадают с последовательным счётом. Работает и из папки, и в установленной копии.

## Решения мастера проекта (не обсуждать, применять)
1. **Многоточечные расчёты идут в движок напрямую, минуя verified-лизу** (`thermogar_verified_loaders` /
   `VerifiedB3BatchBroker`): лиза сериализует бэкенд по одному вызову и была частью Codex-процесса. SHA базы движок
   проверяет сам. Одиночная точка остаётся на verified-маршруте. Квитанции/строки «Набор фаз», история и экспорт для
   сканов должны заполняться так же, как сейчас — переиспользуй существующие функции сборки результата
   (`summarize_equilibrium`, `aggregate_phase_fractions`, `record_calculation_history`), подавая им результаты движка.
   Если какой-то из них нужен объект `eq` pycalphad, а движок отдаёт словари — сделай тонкий адаптер, не меняя функции.
2. **Число воркеров** = `min(cpu_count-1, свободная_память_ГБ // 1.5, 6)`, не меньше 1; определяется при первом
   создании пула (`psutil` есть в venv? иначе `ctypes`/`GlobalMemoryStatusEx`). В сайдбаре — «Параллельный расчёт:
   авто (N воркеров) / выкл.» — без ручного числа.
3. **Порог**: пул используется при числе точек ≥ 4 (Al ≥ 2); меньше — последовательно в процессе, как сейчас.
   Тёплый пул живёт как module-level singleton с ключом (путь, SHA, воркеры); пересоздаётся при смене базы.
   Закрытие: `atexit` + при остановке лаунчер убивает Job целиком, дети умрут — проверить, что Job охватывает внуков.
4. `PYTHONHASHSEED=0`: в `RUN_THERMOGAR_WINDOWS.cmd` и в окружении дочернего Streamlit в `packaging\launcher.pyw`.
5. Прогресс: `st.progress` через callback движка, с текстом «точка i из N».
6. Fallback: любая ошибка пула (нехватка памяти, `WorkerLostError`) → сообщение и последовательный досчёт
   оставшихся точек, результат не теряется.
7. Ленивый `import scheil` (2,1 с на старте, 5C не могла — верхний уровень `ThermoGar_app.py`): импорт при первом
   обращении к разделу «Затвердевание», `SCHEIL_AVAILABLE` вычислять лениво.
