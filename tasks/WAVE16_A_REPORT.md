## Снятия Claude Code и переменная

**Два снятия Claude Code по памяти.** Свободную память в момент снятия не записал ни один
журнал: сторож сценария погибает вместе с сеансом, событий Windows о нехватке памяти
(System, 2004) за 18.09.2026 нет.

1. **18.09.2026, между 14:06:55 и 14:47:54** (`run_2.log`). Задание 16/476 —
   В96ц1оч, скрипт «Лилит», `--nabor polnyj`, 1e-9. Сторож стоял на 1,0 ГиБ. После
   этого снятия мастер убрал `polnyj` из плана и поставил сторож «Лилит» на 2,0 ГиБ.
2. **18.09.2026, между 22:48:11 и ~22:55** (`run_3.log`). Задание 105/191 —
   16Х11Н2В2МФ, `mc_fe_2062_patch`, скрипт «Лилит», `sloj`, 1e-9 (id `9cb04512dd2c1cdc`).
   Сторож стоял на 2,0 ГиБ и не сработал. Отсюда вывод, но не замер: Claude Code снял
   оболочку раньше, чем свободная память упала ниже 2,0 ГиБ. Это задание пересчитано с
   нуля: пик 8,3 ГиБ, на входе свободно 10,4 ГиБ, минимум 5,4 ГиБ, 175 с,
   1687,1 / 1762,1 K.

**Почему переменная включена.** Claude Code сам снимает фоновую оболочку, когда свободной
памяти мало, и снимает весь сеанс исполнителя. Этот порог срабатывает раньше сторожа
сценария (2,0 ГиБ) и выше аварийного `E1_ABORT_FREE_GIB` (1,0 ГиБ). По решению мастера
сеанс запущен с `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1`: память охраняет только
сторож сценария. Переменная проверена в начале сеанса: `1`. После этого снятий Claude Code
не было. Чтобы при следующем снятии цифра не потерялась, свободная память пишется каждые
10 с в `results/wave16_a/logs/svobodno_run4.log`.
