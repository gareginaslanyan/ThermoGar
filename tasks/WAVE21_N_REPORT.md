### а) Как строится ось состава

- `tzero_path_table` (`app/ThermoGar_app.py:4294`). При ат.% ось — `v.X(элемент)`, постоянные добавки — `v.X` (`:4352–4357`). При мас.% ось — `v.W(элемент)`, добавки — `v.W` (`:4358–4363`). Условие оси — кортеж `(c_min/100, c_max/100 + 0,5·шаг/100, шаг/100)` (`:4365–4371`). pycalphad разворачивает его в `np.arange` (`pycalphad/core/utils.py:94`). Для `v.X` значения зажаты в [1e-10; 1 − 1e-10] (`core/workspace.py:39–44`), для `v.W` — нет.
- Порядок точек: одна переменная ось, точки идут по возрастанию. Строка `i` = `c_min + i·шаг`: строка 0 — 0 мас.%, строка 3 — 0,3 мас.%, строка 20 — 2,0 мас.%. `Workspace.get_dict` обходит `np.ndindex` по сетке условий (`core/workspace.py:498–524`).
- Общий `path_workspace` — двухфазное равновесие [фаза 1, фаза 2] при **одной** температуре: середина окна, `T = (t_min + t_max)/2` (`:4372`). По умолчанию это 1000 °C, в К-4 — 680 °C.
- Столбец состава: `100·workspace_values(path_workspace, axis_variable)` (`:4417–4420`). Это **не** заданная сетка, а свойство, пересчитанное из результата равновесия. `MoleFraction.compute_property` / `MassFraction.compute_property` (`pycalphad/variables.py:568–579`, `:702–718`) суммируют по наборам фаз точки. Если наборов нет, результат — NaN.
- Когда наборов нет: решатель равновесия в точке не сошёлся. Тогда `eqsolver.pyx:289–295` пишет `Phase = ''`, `NP/X/Y/GM = NaN`. `enumerate_composition_sets` пропускает фазы `''` (`core/workspace.py:452–480`, пропуск — `:471`), список наборов пуст, и состав в строке — NaN («None» на экране).
- Условие «состав пуст, T₀ конечна»: в этой точке двухфазное равновесие при середине окна не сошлось, а поиск T₀ сошёлся. Эти расчёты независимы (см. б).

### б) Что такое T₀ в этих строках

- `T0.compute_property` (`pycalphad/property_framework/tzero.py:64–97`) **не использует** наборы фаз равновесия (`equilibrium_compsets`). Он берёт `cur_conds` точки, то есть **заданную** сетку: `W(C) = c_min + i·шаг`, добавки, P, N, и `T` = середина окна как стартовое значение. Далее он решает каждую фазу отдельно (`Solver.solve([фаза], conditions)`) от своих стартовых наборов из однофазных `Workspace` (`app/ThermoGar_app.py:4387–4396`).
- Итерация по T: шаг `−ΔG/(2·dΔG/dT)`, T зажата в окне [t_min; t_max] (`tzero.py:82–92`). Остановка при `(G₁ − G₂)² < 0,01`, то есть |ΔG| < 0,1 Дж/моль, не более 50 итераций. Если за 50 итераций невязка не ушла, результат — NaN (`:95–96`).
- Вывод по коду: конечная T₀ — корень G(BCC_B2) = G(FCC_A1) в окне при **заданном** составе строки (C = 0,3; 0,4; … мас.%). Это не стартовое значение: старт 1000 °C, а в таблице 1563–1680 °C. Это и не граница окна: на 1700 °C итерация не остановится, пока |ΔG| ≥ 0,1 Дж/моль. Точка не вне пути: состав берётся из той же сетки.
- Пустой состав — артефакт показа. Столбец берётся из несошедшегося двухфазного равновесия, а не из заданной сетки.
- Вторая часть BL-66 — **ветка корня**. У Fe–C при одном составе два корня T₀(BCC, FCC): нижний (α/γ, 911 °C при 0 % C, убывает с C) и верхний (δ/γ, растёт с C). Итерация Ньютона идёт от середины окна и сходится к тому корню, к которому её ведёт наклон. В строках 0–2 она нашла нижний корень, в строках 3–11 — верхний. При 0,3 мас.% нижний корень 689,3 °C есть (К-4), в окне 300–1700 он тоже лежит, но от 1000 °C итерация ушла к 1563 °C. Окно 300–1700 °C шире рабочего окна из подписи на экране («Fe BCC_B2/FCC_A1 630–730 °C», `:11620`) и накрывает обе ветки.
- Что по коду не определить (нужен прогон, п. П-1…П-3): почему двухфазное равновесие при 1000 °C не сходится с 0,3 мас.% C; совпадает ли граница «состав пуст» со сменой ветки (обе начинаются со строки 3) случайно; какие из строк 12–20 дают T₀.

### г) Предложение: что считать найденным

Условие по коду: строка найдена, если `np.isfinite(tzero_k)`. Это значит, что при **заданном** составе строки |ΔG| < 0,1 Дж/моль достигнуто внутри окна. Признак «Решение найдено» (`:4428`) и счётчик (`:11711`) менять не нужно. Менять нужно столбец состава: брать его из заданной сетки, по которой T₀ и считалась. Тогда счётчик, таблица и график сходятся: n строк с «Решение найдено» = n точек на графике, у каждой есть состав.

Набросок (не в `app/`):

```python
    composition_grid = 100.0 * np.arange(
        float(c_min) / 100.0,
        float(c_max) / 100.0 + 0.5 * float(c_step) / 100.0,
        float(c_step) / 100.0,
    )  # тот же кортеж, что в conditions[axis_variable]; pycalphad строит сетку так же
    composition_axis = 100.0 * workspace_values(path_workspace, axis_variable)
    tzero_k = workspace_values(path_workspace, tzero_property)
    composition_axis = np.where(
        np.isfinite(composition_axis), composition_axis, composition_grid
    )
    return pd.DataFrame(
        {
            f"{variable_element}, {'ат.%' if units == 'at' else 'мас.%'}": composition_axis,
            "T₀, °C": tzero_k - 273.15,
            "T₀, K": tzero_k,
            "Решение найдено": np.isfinite(tzero_k),
        }
    )
```

- `np.where` сохраняет все нынешние конечные значения (включая «1e-8» в строке 0) и заполняет только пустые. Можно брать сетку целиком (`composition_axis = composition_grid`), тогда путь равновесия нужен только как перебор точек.
- Таблица: все строки с составом; «Решение найдено» — как сейчас. График (`plot_tzero`, `:4444`): без правки — `dropna(subset=["T₀, °C"])` даст те же n точек, что и счётчик.
- Тексты — только существующие: «T₀ найдено в {n} точках из {m}.» (`:11715`); при n < m — `:11719–11722` («…В остальных точках перехода в заданном окне нет: сдвиньте окно к ожидаемой температуре перехода.»); при n = 0 — `:11724–11731`.
- Ожидаемо для стали по умолчанию после правки: «T₀ найдено в 15 точках из 21.» (как сейчас), но на графике 15 точек вместо 3. Линия пойдёт 911,7 → 735,9 °C (нижняя ветка), затем скачок к 1563 °C (верхняя). Это честный показ, но две ветки на одной линии. Вопрос к владельцу, отдельно от BL-66: сузить окно T₀ по умолчанию для fe. Для этого нужен отдельный ключ (сейчас `t_min/t_max` общие для «Энергий фаз», «Движущей силы» и T₀: `:11066/11072`, `:11334/11340`, `:11624/11630`). Окно из подписи 630–730 °C при C 0–2 мас.% даст мало точек, окно подбирать прогоном (П-3).
- Отвергнуто: считать найденными только строки с конечной T₀ **и** непустым составом (сейчас было бы 3 из 21). Оно выбрасывает верные корни при известном составе, а причина пустого состава не связана с T₀.
