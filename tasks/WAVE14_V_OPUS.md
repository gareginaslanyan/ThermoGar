# Задача 14-В — исправление признака BL-32

Задание мастера, дословно.

```
Задача 14-В. Исправление признака BL-32. Отчёт 14-Б принят, кроме этого.

ПРИЗНАЮ ОШИБКУ МАСТЕРА: признак «радиус зажат на Rmin» был выведен из
совпадения на пяти случаях 14-А и оказался слишком широким. Разбор 14-Б
(умолчание Ni-раздела считается при зажатом радиусе) его опроверг. Ни
умолчания, ни тесты не трогать — они правильные.

НОВЫЙ ПРИЗНАК, вывод прилагается.
Барьер зарождения при радиусе R относительно настоящего:
    dG(R)/dG* = 3u^2 - 2u^3,  где u = R / r*,  r* = 2*gamma/dGv.
Когда kawin зажимает радиус, он считает барьер при u = Rmin/r*.
Уравнение 3u^2 - 2u^3 = 0 даёт u = 1.5, то есть барьер обращается в ноль
при r* = (2/3)*Rmin.

  - r* >= Rmin                -> ничего, зажима нет;
  - (2/3)*Rmin < r* < Rmin    -> ПРЕДУПРЕЖДЕНИЕ, не отказ. Барьер
    положительный, но занижен; в сообщении указать, во сколько раз
    (посчитать 3u^2 - 2u^3 и дать процент занижения);
  - r* <= (2/3)*Rmin          -> ОТКАЗ. Барьер неположителен, скорость
    зарождения ничем не сдерживается, расчёт не сходится.

1. Переписать _check_critical_radius_floor под этот признак. Порог (2/3)
   вычислять из формулы в коде с комментарием-выводом, а не вписывать
   числом 0.2 нм. Rmin по-прежнему читать из kawin.

2. Сообщение отказа — три предложения, как раньше, но причина другая:
   критический радиус настолько меньше предела модели, что барьер
   зарождения обращается в ноль. Сообщение предупреждения — отдельное,
   в warnings: барьер занижен на N %, начало выделения на графиках
   наступает раньше действительного, итоговые доля и размер затронуты
   слабее.

3. ПРОВЕРИТЬ ПРИЗНАК НА ВСЕХ ИЗВЕСТНЫХ СЛУЧАЯХ и привести таблицей
   <случай | r*, нм | u | 3u^2-2u^3 | что даёт новое правило | что было
   на самом деле>:
   - пять зависших случаев 14-А (А5, А6, А7, C4 штатным путём, и А5
     первого прохода) — для C4 и А7 незажатый r* в 14-А не выписан,
     посчитать;
   - умолчание Ni-раздела (800 C, gamma 0.023);
   - ступень Б5 и ступень 4 лестницы А.
   Если хоть один зависший случай новое правило НЕ отклоняет либо
   умолчание Ni отклоняет — остановиться и доложить, не подгоняя порог.

4. Тесты BL-32 переписать под новый признак, сохранив приём 14-Б с
   подменой solve на AssertionError. Добавить тест на границу: случай
   чуть выше (2/3)*Rmin проходит с предупреждением, чуть ниже —
   отклоняется.

5. Прогнать test_ui_g целиком (-m "not slow" и -m slow): оба прежде
   красных теста должны стать зелёными без правки самих тестов.

6. Повторить побайтовую сверку пункта 6 отчёта 14-Б. Должно снова
   совпасть с main.

7. Регрессия — только файлы, которых касается правка:
   test_precipitation_grid, test_ui_g, test_backend_calculations,
   thermogar_precipitation_test, thermogar_self_test. Остальное прогнано
   в 14-Б на том же коде.

8. В REGISTER.md поправить запись BL-32: признак уточнён в 14-В, прежний
   был слишком широк, причина ошибки — мастера, вывод нового признака
   записать.

9. Отчёт tasks/WAVE14_V_REPORT.md: таблица пункта 3 первой, затем
   результат пункта 6. git log --oneline, git status --short.
   В main не вливать.
```

Дерево `ThermoGar-w14a`, ветка `wave14-kwnlimit` — продолжение 14-Б. Волна владеет
