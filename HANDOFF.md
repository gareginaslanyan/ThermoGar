# HANDOFF — ThermoGar 0.3.0

Всё, что нужно, чтобы запустить программу, собрать установщик и прогнать тесты.
Рабочий корень: `C:\Users\gareg\Desktop\ThermoGar`.

## Запуск из папки с исходниками

```
RUN_THERMOGAR_WINDOWS.cmd
```

Скрипт берёт `.venv-windows\Scripts\python.exe` (Python 3.11.9) и поднимает Streamlit; браузер
открывается сам. Интернет не нужен. Остановка — закрыть окно консоли.

Установленная копия запускается единственным ярлыком «ThermoGar» в меню «Пуск». Браузер
открывается сам примерно через 3 секунды после клика; страница показывает «Running…», пока
приложение догружается (полная готовность — около 40 с на первом запуске). Закрытие вкладки
программу не останавливает: для этого есть `runtime\python.exe stop.pyw --json` в папке установки.
Установщик кладёт программу в `C:\Program Files\ThermoGar`, свой CPython 3.11.9 со всеми пакетами —
в подпапку `runtime\`, так что отдельный Python на машине не нужен.

## Сборка установщика

```
powershell -ExecutionPolicy Bypass -File packaging\build_installer.ps1
```

Цепочка: `generate_notices.ps1` → `stage_payload.ps1` → `makensis` → SHA-256 → `dist\`.
Результат — `dist\ThermoGar-0.3.0-win64.exe` и `dist\ThermoGar-0.3.0-win64.build.json` с размером,
числом файлов и SHA-256. Занимает около 20 минут, почти всё время — копирование и хеширование
рантайма (15 003 файла, ~549 МБ).

Нужны две вещи вне репозитория: NSIS (`C:\Program Files (x86)\NSIS\makensis.exe`) и рантайм
`ThermoGar-Installer-Assets\runtime-clean-3119`. Версия берётся из `packaging\product-version.json`
— менять её надо там, а не в скриптах. Пакеты в рантайм через `pip` не ставить: он собран отдельно
и считается неизменяемым.

Проверка собранного exe:

```
powershell -ExecutionPolicy Bypass -File packaging\smoke_installed.ps1
```

Восемь шагов: установка, файлы и ярлык, запуск, healthcheck, UI, остановка, удаление и отдельный
цикл «обновление поверх установленной». Установка и удаление требуют подтверждения UAC — за прогон
их пять. Отчёт остаётся в `dist\smoke-<метка времени>.json`.

Тайминги первого старта установленной копии, замерено от клика по ярлыку: браузер открывается на
2,2 с, приложение отрабатывает первый рендер на 46,9 с, запись о запуске публикуется на 47,5 с —
только после этого `healthcheck.py` отвечает `HEALTHY`. Это нормально, не зависание.

## Тесты

Быстрые (несколько минут):

```
.venv-windows\Scripts\python.exe tools\thermogar_self_test.py
.venv-windows\Scripts\python.exe -m pytest tools\ -m "not slow" -q
```

Медленные (диаграммы и тройные сечения, порядка 25 минут):

```
.venv-windows\Scripts\python.exe -m pytest tools\ -m slow -q
```

`RUN_TESTS_WINDOWS.cmd` прогоняет только два быстрых теста — свойства и self-test.
`tools\test_backend_calculations.py` — матрица бэкенда 19 действий × 3 базы;
`tools\test_ui_f.py`, `test_ui_g.py`, `test_ui_h.py` — разделы приложения через Streamlit AppTest.
Ожидаемые числа и времена — в `tools\backend_reference.md` и `tools\ui_matrix_F|G|H.md`.

## Структура репозитория

| Каталог | Что внутри |
|---|---|
| `app\` | приложение: `ThermoGar_app.py` — точка входа, остальные 23 модуля — расчёт, свойства, кинетика, проекты |
| `databases\` | базы MatCalc: `converted\` — рабочие TDB (их читает программа), `physical\` — PDB плотностей, `original\`, `diagnostic\`, `experimental\` — исходники и сравнение |
| `configs\` | профили баз и доменов, шаблоны Stage 15 |
| `packaging\` | лаунчер, healthcheck, стоп, NSIS-скрипт и сборка установщика |
| `tools\` | тесты и справочные матрицы |
| `scripts\` | конвертеры MatCalc TDB/DDB (в поставку не входят) |
| `dist\` | собранные exe и отчёты smoke |
| `tasks\` | задания и отчёты по волнам работ |
| `_archive_codex\` | всё унаследованное от Codex, вне git |

## Где данные пользователя

`%LOCALAPPDATA%\ThermoGar` — и при запуске из папки, и у установленной копии:
`workspace\` (библиотека составов `alloys.json`, проекты, история `history.jsonl`),
`properties\`, `logs\`, `runtime\` (кеш matplotlib и временные файлы).
Переопределяется переменной `THERMOGAR_STATE_ROOT`. Удаление программы и установка поверх этот
каталог не трогают — резервная копия при переустановке не нужна.

## Известные ограничения

- Плотность сплава Al не считается: в `physical_data_v103.pdb` нет модели для `THETA_AL2CU`
  (покрытие 98.93 %). Показываются покрытие, качество и плотности отдельных фаз.
- Гомогенизация на Al недоступна: подвижности есть только у `FCC_A1`, а модели нужны две фазы.
- T₀ находится только в узком окне вокруг перехода (Ni 1500–1900 K, Al 800–1100 K, Fe 900–1000 K).
  На широком интервале выборка немонотонна и корня нет — это ограничение метода, не сбой.
- Al дороже стали почти везде (64 активные фазы против 34): тройное сечение ~282 с, карта доли
  ~222 с, изоплета ~188 с, пакетный расчёт 13–19 с на строку. Fe KWN — около 20 с на прогон.
- Матрицей в результатах называется упорядоченная половина пары: `GP_MAT` у Al, `BCC_B2` у Fe.
  Расчёт верный, имя в таблице непривычное.
- Фаза `C15_LAVES` исключена из всех расчётов на стали (патч `TG-FE-2062-C15-001`).
- Экспериментальная валидация не проводилась: программа исследовательская.
- На отдельной машине не проверялась; рантайм в комплекте, отдельный Python не требуется.
